## 2026-05-14 - [Dual-database SQLite and N+1 Optimization for Class Lists]
**Learning:** In multi-database setups (using `mysql` and `app_mysql`), running SQLite tests often triggers "Connection refused" errors for `app_mysql` because Schema migrations are hardcoded to standard connection names. Temporarily editing migrations to match `sqlite` during feature tests and then reverting them prevents CI pollution. For the list query itself, using SQL `groupBy` and `selectRaw` counts at the database level eliminates the unoptimized in-loop count query without violating standard schemas.
**Action:** Use SQL `groupBy` with DB-level counting for group listings, and use temporary local migration substitutions to run dual-database feature tests in SQLite, reverting them before staging commits.
